Full Duplex Authentication sits behind the supported app-based experience. Map the application, configured authentication service and enrolled device before deciding where the person confirms the request.

The application owns the final access decision.

    Starts the request and owns the account, session and permissions.

  3. Configured integration

  6. device interaction →
  7. Enrolled device

A federated application is a concrete starting point.

For a configured SAML or OpenID Connect integration, NoPass acts as the identity provider. The relying application requests authentication, NoPass handles the enrolled-device exchange, and the application uses the result to apply its access policy.

The application keeps its business functions and permissions. The account source and user mapping connect the existing identities to the chosen configuration.

Working in a Microsoft environment.

For Windows workstation access, start with Desktop Unlock. For a directory-backed business application, connect its account mapping and the applicable federation configuration. These are distinct access points, with their own setup guidance.

The integration team can identify the supported configuration for your Windows, directory or federation environment.
