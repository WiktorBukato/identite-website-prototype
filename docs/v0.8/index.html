A valid credential is not the whole interaction.

Some attacks do not defeat authentication at all. They try to persuade a legitimate user to respond to the wrong destination or approve an unexpected request.

The user, the service and the request all matter.

Verifiable identity is the cornerstone of digital trust.

Full Duplex Authentication connects account authentication, the enrolled app’s server relationship and a deliberate human decision. The comparison is the visible part of that experience.

  1. Requesting application

    Starts the request and owns account access or the pending operation.

  2. Authentication request
  3. NoPass™ authentication server

    Handles the configured authentication exchange.

  4. Established server ↔ app relationship
  5. Enrolled app

    Verifies its established authentication-server relationship.

  6. Visible comparison and decision
  7. The person

    Checks the request they initiated or expected, then chooses.

Identity

Who is participating?

Authenticate the enrolled account with the configured factors.

Destination

Is this the connected service?

The enrolled app checks its authentication server; the integration connects that server to the application.

Intent

Is this the request I meant to approve?

A request can be expected without being initiated by the person, such as an agent-prepared action. The person still decides.
